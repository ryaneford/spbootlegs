How to use spbootlegs

1. Find a bootleg

Paste any of the following into the URL box:

  • SPLRA release page — the main source for bootleg metadata, lineage, and setlists
  • SPLRA tour page — lists all surfaced recordings; archive.org links resolved automatically
  • Archive.org details page — paste directly; band is detected from the identifier prefix (tsp, zwan, bc)

SPLRA pages are fetched through FlareSolverr to bypass Cloudflare. Video recordings (PRO, AMT, VHS, TV sources and video formats) are automatically rejected.

2. Select a recording

On tour pages, audio recordings with archive.org links are clickable. The app checks peer count before letting you start — if a torrent has zero seeders, the download button is disabled. You can edit band, date, venue, city, state, and source before starting.

3. Download

The torrent file is fetched from archive.org and handed to WebTorrent. Progress, speed, and peer count are shown in real time.

Stall fallback: If the torrent gains less than 1% in 5 minutes (common for old archive.org torrents with sparse seeders), it's automatically cancelled and download switches to direct HTTP from archive.org's CDN. Files already fully downloaded by the torrent are skipped. Each file is retried up to 3 times on transient errors.

4. Automatic post-download pipeline

Once the download completes (torrent or direct), this pipeline runs in sequence:

  1. Cache — raw files are saved to CACHE_DIR for re-processing later without re-downloading
  2. Track titles — resolved in priority order: archive.org _files.xml > NFO files in the download > SPLRA setlist text
  3. Rename — directory renamed to Artist - YYYY-MM-DD - Venue - City, ST; files renamed to dXtYY - Track Title.ext
  4. SHN → FLAC — any .shn files are converted via shntool + flac
  5. Format filter — non-audio files and duplicates removed; only the best available format is kept per track
  6. Tag — ID3/Vorbis tags written locally for MP3/OGG; FLAC files are deferred and tagged remotely via metaflac after transfer (avoids re-copying large files)
  7. Cover art — folder.png generated with band logo, date, venue, and city
  8. Transfer (optional) — if SP_SSH_HOST is configured, files are SCP'd to your NAS/server over SSH
  9. Verify — file sizes compared 1:1 after transfer; local files deleted only if verified
  10. Remote tag — if transferred, metaflac is called over SSH to write tags directly on the destination

5. Listen (optional)

If you configure ND_BASE/ND_USER/ND_PASS, the right sidebar shows recently-added albums from your Navidrome library and lets you generate share links. This is entirely optional — the downloader works fully without it.

Re-processing from cache

The Cache tab shows all raw downloads saved before processing. You can re-process any of them (e.g. to pick up a setlist fix or re-tag) without re-downloading. This runs the full pipeline from rename onward.

Orphaned downloads

The Orphaned tab shows directories in DOWNLOAD_DIR that have no associated job. These can be transferred to your NAS/server directly, useful for manually placed files.
